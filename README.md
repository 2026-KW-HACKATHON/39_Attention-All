# 우이런 (UI RUN)

> **달리고 걸으며 환경 참여를 일상화하는 월계1동 우이천 ESG 플랫폼**

2026 광운대학교 KW해커톤 **39조 일동차렷** 프로젝트입니다.

우이런은 월계1동 생활권의 우이천을 중심으로, 주민과 광운대생이 이미 반복하고 있는 **러닝·산책·통행**을 환경 참여의 진입점으로 활용합니다.

환경 제보를 먼저 요구하기보다, 우이천을 이용하는 과정에서 필요한 정보를 제공하고 필요한 순간에만 가볍게 참여하도록 설계합니다.
사용자가 남긴 관찰은 **최초 발견 → 재확인 → 해결 확인**으로 이어지며, 유효한 기여는 포인트와 월계1동 지역 혜택으로 연결합니다.

---

## 1. 프로젝트 배경

월계1동 서측을 흐르는 우이천은 주민과 광운대생이 걷고 뛰는 생활공간입니다.

하지만 우이천의 환경·시설 상태는 계속 변하고, 다음과 같은 문제가 있습니다.

- 환경 이상이나 시설 문제를 발견해도 기록이 일회성으로 끝나기 쉽습니다.
- 같은 문제가 계속되고 있는지, 해결됐는지 다시 확인하기 어렵습니다.
- 진입점, 징검다리, 화장실, 쉼터, 코스 등 우이천 이용 정보가 여러 서비스와 데이터에 흩어져 있습니다.
- 주민에게 환경 제보 자체만 요구해서는 지속적인 참여를 만들기 어렵습니다.

실제 우이천에서는 **2025년 3~4월 유지용수 관로 차단·누수로 건천화, 악취, 생태계 피해가 반복적으로 발생**했습니다.
또한 2024년 월계1동 행정사무감사에서는 우이천 예찰과 관련해 **하천순찰대 8명 운영 및 현장 확인 인력의 한계**가 언급됐습니다.

우이런은 이 문제를 **“환경 참여를 어떻게 반복 가능한 일상 행동으로 만들 것인가”**에서 시작합니다.

---

## 2. 핵심 아이디어

우이런은 러닝앱 시장에서 기존 서비스를 대체하려고 하지 않습니다.

사용자는 평소처럼 Samsung Health, NRC 등 기존 러닝앱을 그대로 사용하고, 우이천을 이용할 때 **우이런도 함께 켜는 구조**를 목표로 합니다.

우이런에서는 기존 러닝앱과 별개로 다음과 같은 우이천 전용 가치를 제공합니다.

- 오늘의 우이천 정보
- 월계 구간 전용 지도와 코스
- Eco Check Point
- 환경 참여 포인트
- 월계1동 지역 혜택
- 우이천 전용 인증 카드

```text
오늘의 우이천 확인
        ↓
러닝·산책·통행
        ↓
Eco Check Point 또는 자발적 제보
        ↓
최초 발견 → 재확인 → 해결 확인
        ↓
환경 현장정보 갱신
        ↓
포인트 적립
        ↓
월계1동 지역 혜택
        ↓
다음 이용에서도 다시 참여
```

핵심은 **새로운 환경활동을 따로 요구하지 않고, 이미 우이천에서 하고 있던 행동 안에 작은 참여를 넣는 것**입니다.

## 3. 주요 기능

### 3.1 오늘의 우이천

우이천을 이용하기 전에 필요한 정보를 한 화면에서 확인합니다.

- 기온 / 체감온도
- 습도
- 강수 여부
- 풍속
- 미세먼지 / 초미세먼지
- 최근 구간 상태
- 최근 환경·시설 이슈
- 확인이 필요한 Eco Check Point

단일 점수로 안전 여부를 단정하지 않고, 사용자가 판단할 수 있도록 근거 정보를 함께 보여주는 방향으로 설계합니다.

---

### 3.2 월계1동 우이천 전용 지도

월계1동 생활권과 연결되는 우이천 구간을 초기 **Pilot Area**로 설정합니다.

공공데이터와 현장조사를 결합해 다음 정보를 정리할 예정입니다.

- 진입점
- 계단 / 경사로
- 교량 / 보행교
- 징검다리
- 화장실
- 음수대
- 쉼터 / 벤치
- 주요 시설
- 주요 반환점
- Eco Check Point
- 최근 사용자 확인 상태

기존 지도 서비스를 대체하는 것이 아니라, **우이천 이용에 필요한 정보만 정리한 로컬 레이어**를 만드는 것이 목표입니다.

---

### 3.3 RUN / WALK

러닝과 산책 중 기본적인 이동 정보를 기록합니다.

- 이동거리
- 시간
- 평균 페이스
- GPS 경로
- 구간 기록

검증된 월계 우이천 코스도 제공합니다.

예정 코스:

- 3K
- 5K
- 7K
- 장거리 코스

RUN/WALK 기록은 전문 러닝앱의 운동 분석을 대체하기 위한 기능이 아니라, **우이천 정보와 Eco Check Point를 이동 경로에 연결하기 위한 기능**입니다.

---

### 3.4 Eco Check Point

모든 지점에서 참여를 요구하지 않습니다.

최근 정보가 오래됐거나 재확인이 필요한 지점만 사용자의 경로 위 체크포인트로 제시합니다.

예시:

```text
U05 징검다리
마지막 확인: 4일 전
최근 강우 이후 상태 확인 필요

현재 상태 확인 +10P
```

또는:

```text
U03 수변 구간
어제 물 위에 거품으로 보이는 영역 제보
현재 상태 재확인 필요

사진으로 재확인 +15P
```

또는:

```text
U07 환경 이슈
3일 전 제보
해결 여부 미확인

해결 상태 확인 +20P
```

참여는 항상 선택형입니다.

러너뿐 아니라 **산책하는 사람, 자전거 이용자, 단순 통행자도 동일하게 참여**할 수 있습니다.

---

### 3.5 환경·시설 제보

이동 중 발견한 문제를 사진과 위치로 기록합니다.

예정 카테고리:

- 쓰레기
- 시설 파손
- 수면·유량 이상
- 거품·오염 의심
- 생물 이상
- 악취
- 통행 문제
- 기타

사진과 함께 위치와 시간을 저장하고, 같은 위치의 기존 이슈와 연결합니다.

AI를 사용하더라도 오염이나 안전 여부를 확정 판정하지 않고 **분류·중복 확인을 돕는 보조 수단**으로만 활용합니다.

---

### 3.6 Observe → Verify → Resolve

우이런은 제보 한 건으로 끝내지 않습니다.

```text
최초 발견
   ↓
재확인
   ↓
해결 여부 확인
   ↓
해결 후 상태 기록
```

같은 지점에 대한 시간 흐름을 남겨 환경·시설 상태의 변화를 확인할 수 있도록 합니다.

사용자 관찰은 공식 행정정보와 구분해서 표시하며, 사용자 제보만으로 안전성이나 오염 여부를 단정하지 않습니다.

**다수 사용자가 재확인한 이슈는 위치·사진·시간·확인 이력을 묶어 행정 전달용 리포트로 정리할 예정입니다.**
현재 주민센터와의 공식 연계는 확정되지 않았으며, 전달 방식은 추후 협의합니다.

---

### 3.7 환경 기여 포인트

문제의 심각도가 아니라 **정보 기여도**에 보상합니다.

예시 정책:

| 활동 | 포인트 |
|---|---:|
| 일반 상태 갱신 | +5P |
| 오래 확인되지 않은 지점 확인 | +10P |
| 유효한 신규 발견 | +15P |
| 기존 이슈 재확인 | +15P |
| 해결 상태 확인 | +20P |
| 중복 / 허위 / 관련 없는 제보 | 0P |

동일 장소 반복 제출, 중복 사진, 위치 불일치 등은 제한하는 방향으로 설계합니다.

---

### 3.8 월계1동 지역 리워드

환경정보 기여로 얻은 포인트를 월계1동 제휴점포 혜택으로 연결하는 것을 목표로 합니다.

예시:

- 카페 할인
- 식당 할인
- 사이드 메뉴
- 음료 제공

```text
우이천 이용
→ 환경정보 기여
→ 포인트
→ 월계1동 상점 혜택
→ 지역 안에서 보상 순환
```

상권 활성화 자체가 주제의 중심은 아니며, **환경 참여 보상이 지역 밖으로 빠져나가지 않도록 하는 지역 순환 구조**입니다.

---

### 3.9 우이천 인증 카드

우이천에서 RUN/WALK를 완료한 뒤 공유 가능한 인증 카드를 제공합니다.

예시:

```text
UI RUN — WOLGYE 5K

Distance  5.02 km
Time      28:41
Pace      5'43"/km
Eco Check 2
```

- GPS 경로
- 거리 / 시간 / 페이스
- 계절별 프레임
- 월계·우이천 전용 디자인
- Eco Check 참여 기록

전문적인 운동 분석 기능이 아니라, **기존 러닝앱을 그대로 사용하면서도 우이런을 함께 켜고 싶게 만드는 추가 경험**으로 설계합니다.

## 4. 차별점

### 4.1 기존 러닝앱을 대체하지 않고, 같이 켤 이유를 만듭니다

Samsung Health, NRC, Strava 등 기존 러닝앱은 운동 기록과 분석에 강점이 있습니다.

우이런은 이 시장에서 기존 앱을 대체하려고 하지 않습니다.

사용자는 기존 앱을 그대로 사용하면서 우이런에서 다음과 같은 **우이천 전용 추가 가치**를 얻습니다.

1. **우이천 정보**
   오늘의 우이천, 진입점, 화장실, 징검다리, 코스, 최근 구간 상태

2. **참여와 혜택**
   Eco Check Point, 환경 기여 포인트, 월계1동 지역 혜택

3. **우이천 전용 경험**
   인증 카드, 계절별 프레임, 우이천 전용 디자인

즉, 기존 앱과 경쟁하기보다 **우이천에서 함께 켜는 앱**을 목표로 합니다.

---

### 4.2 기존 환경 신고 서비스와의 차이

기존 신고 서비스가 행정 접수와 처리에 초점을 둔다면, 우이런은 **같은 현장을 여러 이용자가 반복적으로 재확인하고 해결 후 상태까지 기록하는 구조**를 만듭니다.

또한 문제가 생긴 뒤 사용자가 신고 서비스를 찾아오는 것만 기다리는 대신, 평소 우이천을 이용하는 사람의 동선 안에 Eco Check Point를 배치해 참여 기회를 만듭니다.

---

### 4.3 새로운 행동보다, 이미 하던 행동을 활용합니다

우이런은 환경활동을 위해 별도의 장소나 시간을 요구하지 않습니다.

- 뛰러 왔다가 참여
- 산책하다가 참여
- 자전거를 타다가 참여
- 그냥 우이천을 지나가다가 참여

**이미 우이천에 있는 사람을 환경 참여자로 연결하는 것**이 우이런의 핵심 접근입니다.

---

## 5. ESG 방향성

우이런은 ESG 중 **Environmental(E)** 을 중심으로 설계합니다.

직접적인 목표는 다음과 같습니다.

- 우이천 환경 관찰 빈도 증가
- 환경·시설 이상 현장정보 최신화
- 같은 문제의 반복 재확인
- 해결 여부 기록
- 장기적으로 반복되는 문제 지점 파악
- 주민의 일상형 친환경 참여 유도

부가적으로 지역 주민·학생의 참여와 월계1동 상권 리워드가 연결되며 지역사회 참여 구조를 만듭니다.

우이런은 **검증되지 않은 탄소 절감량을 제시하지 않습니다.**
핵심은 러닝·산책·통행이라는 반복 행동을 통해 **친환경 생활 참여를 지속시키는 것**입니다.

---

## 6. 월계1동 지역성

우이런은 우이천 전체를 처음부터 서비스 범위로 잡지 않습니다.

초기 MVP는 **월계1동 생활권과 직접 연결되는 우이천 Pilot 구간**을 대상으로 합니다.

직접 현장조사를 통해 다음 데이터를 구축할 예정입니다.

- 실제 진입점
- 교량 / 징검다리
- 화장실 / 쉼터
- 주요 러닝 거리
- 주요 반환점
- Eco Check Point
- 구간별 최근 상태

또한 지역 내 제휴점포와 연결해 환경 참여 보상이 월계1동 안에서 순환하도록 설계합니다.

향후 Pilot 구간에서 효과를 검증한 뒤 다른 우이천 구간으로 확장할 수 있습니다.

## 8. AI 활용 범위

AI는 환경 문제를 확정 판정하지 않습니다.

예정 활용 범위:

- 우이천 관련 사진 여부 확인
- 사진 카테고리 추천
- 쓰레기 / 시설 / 수면 상태 후보 분류
- 사진 품질 확인
- 기존 제보와의 중복 가능성 보조

AI 결과는 보조 정보로만 사용하며, 오염·안전 여부를 단정하지 않습니다.

## 11. 검증 지표

우이런의 핵심 가설은 **우이천 이용 경험과 러닝·산책 Hook이 실제 환경 참여로 이어지는가**입니다.

주요 지표:

- RUN/WALK 세션 중 Eco Check Point 참여율
- 유효 제보 비율
- 기존 이슈 재확인률
- 해결 확인 비율
- 해결 확인까지 걸린 시간
- 사용자 재방문율
- 포인트 적립 / 사용 수
- 지역 쿠폰 사용 수

## 12. 개인정보 및 위치정보 원칙

우이런은 GPS 경로와 현장 사진을 다룰 수 있으므로 **최소수집과 목적 제한**을 기본 원칙으로 합니다.

- 위치정보는 서비스 제공에 필요한 범위에서만 사용합니다.
- 공개되는 환경정보는 개인 식별정보와 분리합니다.
- 개인의 RUN/WALK 경로와 환경 제보 위치는 서로 다른 공개 정책을 적용합니다.
- 개인 러닝 경로의 공개 범위는 최소화합니다.
- 환경 통계는 가능한 경우 개인이 식별되지 않는 구간 단위로 집계합니다.
- 사진 업로드 시 불필요한 개인정보 노출을 줄이는 방향으로 설계합니다.

세부 정책은 구현 단계에서 기능 범위와 함께 확정합니다.

## 13. 보안 및 API Key 관리

API Key, 인증정보, 비밀키는 Git 저장소에 포함하지 않습니다.

예정 관리 방식:

- Android 로컬 설정: `local.properties`
- 서버 / 개발 환경변수: `.env`
- Firebase 및 외부 API 인증정보: 환경변수 또는 플랫폼 Secret 사용

`.gitignore`에는 최소한 다음 항목을 포함합니다.

```gitignore
.env
.env.*
local.properties
*.jks
*.keystore
google-services.json
```

> 실제 Firebase 구성에 따라 `google-services.json`의 저장소 포함 여부는 프로젝트 정책과 공식 권장 방식에 맞춰 재검토합니다. 민감한 비밀키는 어떤 경우에도 저장소에 커밋하지 않습니다.

## 14. 데이터·API 및 외부 서비스 출처

현재 기획 단계에서 사용 예정인 데이터·외부 서비스입니다.
실제 구현 시 사용 여부와 라이선스·이용약관을 다시 확인하고, 최종 사용 목록으로 갱신합니다.

| 구분 | 서비스 / 출처 | 용도 | 상태 |
|---|---|---|---|
| 기상 | 기상청 | 기온·강수·풍속 등 | 사용 예정 |
| 대기질 | 에어코리아 | PM10·PM2.5 등 | 사용 예정 |
| 지도 | NAVER Maps API | 지도 및 위치 표시 | 사용 예정 |
| 공공데이터 | 서울 열린데이터광장 / 공공데이터포털 | 하천·시설 관련 데이터 탐색 | 검토 중 |
| 인증·DB | Firebase | Auth·Firestore·Storage | 사용 예정 |
| 웨어러블 | Wear OS Health Services | 운동 데이터 연동 | 확장 기능 |
| AI | Multimodal LLM API | 이미지 분류·중복 판별 보조 | 확장 기능 |

오픈소스 라이브러리를 실제 도입할 경우 이 섹션에 **프로젝트명, 라이선스, 사용 목적**을 함께 기록합니다.
