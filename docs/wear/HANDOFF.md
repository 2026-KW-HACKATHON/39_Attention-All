# 우이런 워치 연결 인계

2026-10-08. 최신 휴대폰 앱을 기준으로 `feat/wear-companion`의 Wear OS 앱과 연결 모듈만 통합했다. 서버 API·참여 정책·기존 제보·기록카드 화면은 변경하지 않는다.

## 설치 조건

- 안드로이드 휴대폰과 Wear OS 3 이상 워치가 먼저 페어링되어 있어야 한다. Tizen 워치와 아이폰은 이 Data Layer 연결을 지원하지 않는다.
- 휴대폰에도 워치 모듈을 포함한 새 APK가 필요하다. 이전 휴대폰 APK만으로는 연결되지 않는다.
- 두 앱의 applicationId는 `com.attentionall.uirun`이고 서명 인증서가 같아야 한다. 팀 테스트용 두 APK는 휴대폰의 기존 서명으로 맞춘다. 인증 키와 APK는 Git에 넣지 않는다.
- 휴대폰에서 로그인·동의·정확한 위치 권한을 준비하고 워치 앱을 연다. 워치가 Firebase에 직접 로그인하지 않는다.

## 좁은 통합 범위

- `watch/`: 팀원이 올린 Wear OS 앱. 연결 확인 직후 `NO_APP`으로 덮이는 경쟁 조건을 수정하고 회귀 테스트를 추가했다.
- `mobile/modules/uirun-wear-bridge/`: 로컬 Expo 모듈, 메시지 수신 서비스, capability, 상태·ACK 전송. `expo prebuild`에서 자동 연결된다.
- `mobile/src/wear.ts`, `wearlogic.ts`, `app/wear-capture.tsx`: 기존 운동·사진 엔진을 사용하는 연결 어댑터와 워치 요청 촬영 화면.
- 기존 파일에는 앱 시작 시 연결 초기화, 운동 시작 동시 요청 보호, 선택 사진 셔터, 워치 알림 성공 시 중복 휴대폰 알림 생략을 연결한다. 기록카드 카메라 복구와 사진 업로드 재시도 수정은 유지한다.
- 휴대폰 버전 0.1.5(code 6), `expo-camera` 의존성과 카메라 플러그인은 새 모듈을 담은 APK 생성에 필요하다.

## 동작

- 워치의 시작은 휴대폰의 기존 운동 준비 화면으로 전달한다. 휴대폰에서 GPS 확인·100m 밖 시작 동의·카운트다운을 마친 뒤 실제 시작 상태가 워치에 전달된다.
- 우이천 100m 밖 참여 제한과 안으로 들어왔을 때 활성화는 기존 규칙을 사용한다. 워치가 이를 우회하지 않는다. 관찰 기준점 재확인의 별도 40m 규칙도 유지한다.
- 거리·시간·기록·보상은 휴대폰/서버가 확정한 값만 표시한다. 워치는 위치나 보상을 자체 계산하지 않는다.
- 일시정지·종료·응답은 기존 엔진으로 처리한다. 시작·재개 때 휴대폰이 잠겨 있거나 뒤에 있으면 휴대폰 확인이 필요하다. 휴대폰 앱이 강제 종료되면 운동 기록을 대신 이어갈 수 없다.
- 현재 서버가 지원하는 `PRESENT` 응답만 제출한다. `ABSENT`/`UNKNOWN`은 지원되지 않음을 안내한다. 서버 정책을 추가하지 않는다.
- 계정 전환 후 이전 계정의 명령·ACK·촬영 연결·상태가 새 계정으로 저장되거나 전송되지 않도록 검증한다.

## 검증과 실기기 확인

자동 테스트는 실제 연결 계층을 대신하는 가짜 전송·위치·서버를 사용한다. 양쪽 명령 해석, 중복 요청, 계정 전환, 연결 복구와 빌드를 검사하며 실기기 페어링 성공을 보장하는 검사는 아니다.

실기기에서는 새 휴대폰 APK와 같은 서명의 워치 APK를 함께 설치한 뒤 연결 준비 상태, 운동 시작/일시정지/재개/종료, 연결 끊김 후 복구, 관찰 알림과 휴대폰 촬영 전달을 확인한다. 연결이 안 되면 [watch/README.md](../../watch/README.md)의 서명·Data Layer 진단 절차를 사용한다.

계약은 [PROTOCOL.md](PROTOCOL.md), 빌드·설치는 [watch/README.md](../../watch/README.md)를 참고한다.
