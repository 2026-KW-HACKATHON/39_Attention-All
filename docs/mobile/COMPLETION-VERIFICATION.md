# 모바일 기능 보완 검증

2026-10-07 KST. 기준 main `48060f5`, 작업 브랜치 `feat/mobile-completion`.

## 구현·자동 검증

위치 준비·카운트다운, 관찰 지도 묶음·나가는 방향, 기존 결과 지도 데이터 처리, 우리 우이천 화면·관찰 안내, 정기 관찰 표시, 안내·상태 문서 정리를 구현했다.

모바일 테스트 38개·타입 검사·린트, 백엔드 144개·문법·웹 검사, 부하 도구 안전장치/통계/재시도 테스트 3개가 통과했다. 새 상태·지도 계산 테스트는 구현 전에 실패를 확인했다. Android Metro/Hermes 번들과 ARM64 개발 APK 빌드 성공. 네이티브 기기 실행·픽셀 검증은 아니다.

## 독립 리뷰와 수정

독립 리뷰에서 중요한 문제 2개를 찾고 한 차례 수정했다.

- `slotsLeft`는 오늘 적립 가능 횟수이며 정원이 아니다. 0이어도 사진 기록을 허용한다. 기존 제한으로 테스트가 실패함을 확인한 뒤 의미·버튼을 수정했다.
- stack PUSH는 기존 준비 화면을 제거하지 않는다. 화면 포커스를 잃으면 준비를 취소하고, 이미 보낸 시작 요청은 유지한다. 완료 화면 이동과 하드웨어 뒤로 가기는 포커스가 있을 때만 처리한다. 포커스 이탈 테스트의 실패를 확인한 뒤 수정했다.

리뷰에서 추가 Minor는 없었다. 지도 화살표는 flat Marker의 rotation으로 지도 회전에 맞춘다.

## 당시 결정과 검증 한계

- 별도 worktree를 만들지 않고 깨끗한 기존 체크아웃에 기능 브랜치를 만들었다. 다른 브랜치를 같은 체크아웃에서 동시에 작업할 수 없다.
- 결과 지도는 이미 키가 있으면 Google 지도를 사용하므로 중복 구현하지 않았다. 기존 validSegments의 거리·속도 필터를 유지한다. 단독 원시 위치점은 기존 필터에 따라 빈 경로로 표시될 수 있다.
- 기존 IBM Plex/Archivo·blue/lime 디자인을 유지했다. 다른 글꼴을 도입하지 않아 기존 브랜드와 일치하며 calm-design의 일반 Pretendard 기준은 적용하지 않았다.
- Store 재구조화는 모바일 변경과 별도 작업으로 남겼다. 당시 [10계정 부하 측정](../api/LOAD-VERIFICATION.md)이 실패했다. 이후 수정·재검증 상태는 해당 부하 검증 문서를 기준으로 확인한다.
- Android 제스처·권한 창·GPS·지도·큰 글자 화면은 미검증이다. 기대와 다른 기기 동작이 남을 수 있다.
- Emulator 시간으로 운영 수용량을 확정하지 않는다. 실제 서비스의 병목과 수용량은 별도 측정해야 한다.
- 관찰 군집에 시설을 섞지 않는다. 인접 시설 마커의 실제 선택성은 기기 확인 항목이며 시설 모드·목록으로 접근할 수 있다.
- 인증 변경 이전에 이미 서버로 보낸 요청은 취소할 수 있다고 가정하지 않는다. 서버 저장 후 해당 계정의 운동 복구가 필요할 수 있다. 준비·응답 반영은 계정 검사로 보호한다.

제휴 상품·약관 확정·릴리스 서명과 Play Integrity, 전체 실기기 검증은 후속 운영 조건이다.

## 머지 전 마무리

시작 요청 응답이 모호하면 서버에 운동이 생성됐을 수 있다는 안내를 표시한다. 단순 연결 실패로 확정하지 않으며 다시 준비하면 기존 startRun의 서버 운동 복구 경로를 사용한다. 회귀 테스트 1개를 추가했다. 지도 키 설정 항목을 env.example에도 추가했다.
