# 모바일 앱 기능 상태

2026-10-06 기준. "Emulator 검증"은 Android Emulator(Pixel 8, API 36) + 로컬 Firebase Emulator(demo-uirun, 사용자 데이터와 분리한 별도 포트·별도 데이터)에서 실제로 눌러 서버 저장·재조회까지 확인한 것만 적는다. 실제 휴대폰과 실제 Firebase 서버(uirun-92539) 검증은 아직 없다. 위치는 `adb emu geo fix`로 만든 가상 위치, 카메라는 Emulator 가상 카메라다.

## 프로토타입 대비

기준: `backend/web/retouch`(OneDrive `uirun-prototype`과 CSS·화면 구성 동일, 서버 연결 부분만 다름). 값은 CSS·마크업에서 옮겼고, 홈은 같은 412×915 화면에서 나란히 비교했다. 운동·결과·카드 화면은 프로토타입이 브라우저 위치 권한 단계에서 진행되지 않아 나란히 비교하지 못했고, 프로토타입 소스 값과 앱 화면을 대조했다.

- 복원: 운동 화면(달리기·산책·간편, 하단 조작부, 종료 시트, 알림 카드), 결과(경로·구간 막대·참여·사실), 사진 기록카드, 기록 탭(기간 막대·간편 최근 카드·날짜별 이력), 참여 상세 시트, 지도(키 없는 그림·간편 목적별), 소식 카드.
- 다른 점: 운동 결과는 지도 키가 있으면 Google 지도 위 경로를 표시하며, 키가 없으면 경로 그림을 표시한다. 지도 키 등록은 완료했다. 지도 SDK 화면의 확대 수준별 묶음(클러스터)·방향 화살표는 넣지 않았다(겹친 핀은 목록으로 연다). 우리 우이천의 머리 사진·지난 기록 접기·‘관찰 정보 읽는 법’ 시트, 정기 관찰 상세 화면은 이번에 다시 꾸미지 않았다. 운동 준비 단계(카운트다운·위치 대기 화면)는 없다(서버 세션을 만든 뒤 바로 기록).

## 알려진 제한

- 앱이 강제 종료되거나 최근 앱에서 지워지면 그동안의 위치는 기록되지 않는다. 다시 열면 서버와 맞춰 복구하고 끊긴 구간으로 표시한다. Emulator(RAM 2.5GB)에서는 부팅 직후 메모리 부족으로 앱이 종료되는 일이 있었다.
- 일시정지·종료를 누른 뒤 늦게 전달된(그 전에 찍힌) 위치 몇 초 분량은 버린다.
- 봉인 요청이 위치를 잰 뒤 10초 안에 서버에 닿지 못하면(오프라인 등) 그 사진은 쓸 수 없고 다시 촬영해야 한다(서버 위치 신선도 규칙, 나중 위치로 대체하지 않음).
- Emulator에서는 RN Firebase Storage 대신 Storage Emulator 업로드 API(multipart, 같은 보안 규칙)를 쓴다. 실제 서버 빌드는 SDK `putFile`을 쓴다(미검증).
- Google 위치 정확도(네트워크 위치) 동의 창은 앱이 띄우지 않는다. 거절된 기기에서는 GPS 최근값(10초 이내)만 쓴다.
- 상승 고도는 표시하지 않는다(기획 결정).
- `expo-media-library`가 매니페스트에 `READ_MEDIA_VISUAL_USER_SELECTED`와 Android 12 이하용 저장소 권한을 넣는다. 앱은 쓰기만 하고(Android 13+는 권한 없이 저장) 사진을 읽지 않는다.
