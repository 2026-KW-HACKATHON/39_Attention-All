# 동시 운동 저장 검증

2026-10-07 KST. 격리된 demo-uirun Emulator, Mac, 실제 로컬 실행 Node 24.14.1, Java 17. 프로젝트/CI 대상은 Node 22이며 운영 서버에는 부하를 보내지 않았다.

## 수정 후 결과

| 계정 수 | 완료 | 논리 요청 | 실패 요청 | 클라이언트 재시도 | p50 | p95 |
|---|---|---|---|---|---|---|
| 1 | 1/1 | 12 | 0 | 0 | 69ms | 459ms |
| 5 | 5/5 | 60 | 0 | 0 | 35ms | 970ms |
| 10 | 10/10 | 120 | 0 | 0 | 33ms | 1944ms |

계정별 동의·운동 시작·홈 조회·GPS 3묶음·종료 동일 ID 재전송·상세·기록 목록을 검증했다. 모든 계정에서 GPS 3점, COMPLETED 상태, 운동 목록 1건을 확인했다. 동일 계정의 동시 동의 재전송은 같은 결과를 반환하고, 서로 다른 ID로 동시에 시작해도 활성 운동은 하나만 생성됐다. 전체 통합 검증도 종료 코드 0으로 완료했다.

요청 시간은 클라이언트 재시도 대기를 포함한다. Firestore 내부 트랜잭션 재시도 수는 SDK에서 노출하지 않는다. 작은 로컬 표본으로 실제 Firestore 지연·운영 수용량을 보장하지 않는다.

## 원인과 변경

수정 전에는 모든 변경이 모든 테이블을 읽고 공통 `internal/meta`를 갱신했다. 10계정 중 5계정만 완료했으며 SERVER_ERROR 4건, LOCATION_STALE 1건, 클라이언트 재시도 29회, p95 72,558ms였다.

`functions/src/store.js`에서 동의·프로필·설정·운동 변경을 계정 단위 트랜잭션으로 분리했다. `internalRunAccounts`는 활성 운동 ID와 대기 포인트 원장 ID를 유지한다. 요청은 필요한 문서를 직접 읽고 해당 계정만 직렬화하며, 운동 시작은 경로 메타 데이터를 읽되 갱신하지 않는다. 기존 계정은 처음 요청할 때 자신의 세션·원장 목록을 조회하여 인덱스를 만든다. 전체 보상·사진·관리자·정리 트랜잭션도 세션/원장을 변경하면 이 인덱스를 갱신한다. 계정 삭제 시 인덱스도 삭제한다.

동일 요청 ID의 receipts, 세션 소유권, 활성 운동 하나 제한, 원래 날짜의 포인트 예산 반환과 계정 삭제 차단을 유지했다. 다른 계정의 대기 포인트 만료는 예약 정리 작업에서 처리한다. 타임아웃이나 위치 신선도 기준은 완화하지 않았다.

보상·사진·관리자 처리에는 전체 스냅샷 트랜잭션이 남아 있다. 이번 결과는 운동 저장 경로의 검증이며 그 밖의 대규모 동시 처리 용량을 의미하지 않는다.

## 재실행

```sh
cd backend
npm run test:integration
```

이 명령은 로컬 demo-uirun Emulator에서 규칙·사진/삭제·API·정리·동시 저장까지 실행하며 CI에서도 사용한다. 다른 사람이 사용 중인 Emulator에서는 실행하지 않는다. 테스트 경로와 계정을 생성하며 종료할 때 자신의 Auth 계정을 삭제한다. Firestore 테스트 기록은 전용 Emulator 종료로 폐기한다.

부하 스크립트를 직접 실행하려면 격리를 확인한 전용 Emulator 주소를 지정한다.

```sh
GCLOUD_PROJECT=demo-uirun \
UIRUN_LOAD_CONFIRM=isolated-demo \
FIRESTORE_EMULATOR_HOST=127.0.0.1:18080 \
FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:19099 \
UIRUN_FUNCTIONS_EMULATOR_HOST=127.0.0.1:15001 \
node verification/load.cjs
```

프로젝트·로컬 주소·격리 확인 중 하나라도 없으면 Admin SDK 초기화 전에 거절한다. 실패 시 종료 코드 1이며 결과는 Git 제외 `output/uirun-load-verification.json`에 남는다. CI는 API 결과와 부하 결과를 artifact로 보관한다.
